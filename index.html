    ☁️ Cloud Sync (Firebase Firestore) — for GitHub Pages deploy

    Connect to Firebase so the dashboard syncs across every device. Once enabled, you update data here and SSMs see it live on their phones.

    1. Go to console.firebase.google.com → Add Project → name it (e.g. dabur-eco).
    2. Inside the project: Build → Firestore Database → Create database (Production mode, region asia-south1).
    3. Build → Authentication → Get started → Sign-in method → enable Anonymous.
    4. Project Settings (⚙️) → Your apps → Web (</>) → register → copy the firebaseConfig object → paste it below.
    5. In Firestore → Rules tab, paste: 
      rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{doc=**} {
      allow read, write: if request.auth != null;
    }
  }
}
    6. Hit Enable Cloud Sync below. Then Push Local → Cloud once to seed the DB.
    Not connected

    ⚠️ Anyone signed-in anonymously can read AND write data — fine for a trusted internal team. For tighter security later, switch to email auth + custom claims and update Firestore rules to request.auth.token.admin == true for write.

    📥 Bulk Upload — Historical / April Data (CSV)

    Upload many days of ECO numbers in one go (perfect for backfilling April, last month, etc.).

    1. Click ⬇️ Download Template — gives you a CSV pre-filled with your SSMs.
    2. Open it in Excel. Fill one row per (date, SSM). Use the date format YYYY-MM-DD (e.g. 2026-04-15).
    3. Each SKU is a column. Enter the raw ECO count (number of outlets), not the percentage.
    4. Save as CSV and click ⬆️ Upload CSV.
    Column order: date, ssm_id, ssm_name, real1l, real125, real200, realPet, activ1l, realActivCwApet, realActivCwPet, koolerzDrinks, koolerzPet, hajmola
    real1l is the base — every other SKU's ECO% is computed as (SKU ÷ real1l) × 100.
